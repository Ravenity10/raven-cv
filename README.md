# John Raven M. Delos Reyes - WordPress Developer Portfolio

A single-page portfolio built with Vite, React, Tailwind CSS v4, Motion and Lenis.
The production build is pre-rendered to static HTML, so it can be hosted anywhere that serves files.

## Requirements

- Node.js 20 or newer (built and tested on Node 24)
- npm

## Install

```bash
npm install
```

Playwright's browser is only needed for the screenshot script:

```bash
npx playwright install chromium
```

## Run

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server with hot reload at http://localhost:5173 |
| `npm run build` | Production build into `dist/`, then pre-renders the page HTML |
| `npm run preview` | Serves the `dist/` build locally to check it before deploying |
| `npm run screenshots` | Captures project screenshots (see below) |
| `npm run brand-assets` | Regenerates the favicons and `public/og-image.png` |

## Project structure

```
index.html              SEO and Open Graph meta, no-flash theme script
src/
  data/                 All site content
    profile.js          Name, contact, YEARS_EXPERIENCE, copy for every section
    skills.js           Skill groups and toolbox
    experience.js       Work history and education (from the CV)
    projects.js         Reads scripts/sites.json and screens.json (no content of its own)
    screens.json        Generated by the screenshot script
  components/           Header, Hero, About, Skills, Projects, ProjectCard, ProjectModal,
                        Experience, Services, Contact, ThemeToggle, Footer, plus CvLink,
                        Reveal and SectionHeading
  hooks/                useTheme, useSmoothScroll (Lenis)
  entry-server.jsx      Build-time render used by scripts/prerender.mjs
scripts/
  sites.json            Project list (the source of truth for the Projects section)
  screenshot.mjs        Playwright screenshot capture
  prerender.mjs         Writes the rendered HTML into dist/index.html
  brand-assets.mjs      Favicon and OG image generator
public/
  screens/              <slug>.webp (1200px) and <slug>-sm.webp (640px)
  cv/                   The downloadable CV (PDF)
```

Components contain no content. To change wording, edit the files in `src/data/`.
Years of experience is a single constant, `YEARS_EXPERIENCE`, in `src/data/profile.js`.

## Updating the CV

Replace `public/cv/John_Raven_Delos_Reyes_Resume.pdf` with the new PDF (same file name), then update
`src/data/experience.js` if roles changed. To use a different file name, change `profile.cv` in `src/data/profile.js`.
The CV is linked from the header, hero, Experience and Contact sections. Note that the PDF is public once deployed,
including the phone number in it.

## Adding or editing a project

1. Add an entry to `scripts/sites.json`:

   ```json
   {
     "name": "Example Site",
     "url": "https://example.co.uk",
     "description": "One or two sentences about the site.",
     "features": ["Three or four specific things that were built"],
     "tags": ["WooCommerce", "ACF"],
     "evidence": "Optional note on where the details came from (not shown on the site)"
   }
   ```

   The slug (used for the screenshot file name) is generated from `name`, for example `example-site`.
   Order in the file is the order on the page.

2. Capture its screenshot. Pass part of the slug to capture just that site:

   ```bash
   npm run screenshots -- example-site
   ```

   Run `npm run screenshots` with no argument to refresh every site.

3. Restart `npm run dev` or rebuild.

If a capture fails, the card shows a styled placeholder with the site name instead of an image.

### Reviewing inferred content

Any description or feature in `sites.json` that starts with `[inferred]` was deduced rather than confirmed
from project files (for example, from a plugin being present in a folder rather than known to be active).
The prefix is stripped on the page, so the text is visible. Confirm or edit it, then delete the prefix.

### How the screenshot script works

- Chromium at 1440x900, English (UK) locale, reduced motion.
- Waits for the page to load, then for network idle (best effort, up to 20 seconds, because chat widgets and
  analytics can keep the network busy indefinitely).
- Hides common cookie banners and popups with CSS. It does not click them, so no consent choice is recorded.
  Add selectors to `HIDE_CSS` in `scripts/screenshot.mjs` if a banner still shows.
- Saves WebP at quality 80: a 1200px version for the modal and a 640px version for the cards.
- Failing sites are skipped and listed at the end. Sites behind a firewall or bot protection
  (HTTP 403 for automated browsers) will fail. In that case, take a 1440x900 screenshot manually, save it as
  `public/screens/<slug>.webp` and `public/screens/<slug>-sm.webp`, and add the slug to `src/data/screens.json`:

  ```json
  "example-site": { "width": 1200, "height": 750 }
  ```

## Theme

- Light and dark themes use Tailwind's class strategy (`.dark` on `<html>`).
- The first visit uses the dark theme. Choosing a theme with the toggle saves it in `localStorage`.
- An inline script in `index.html` applies the theme before first paint, so there is no flash.
- Colour tokens are CSS variables in `src/index.css`. Every text colour pair meets WCAG AA in both themes.

## Motion and accessibility

- Smooth scrolling with Lenis. It is not started when the OS asks for reduced motion.
- Hero text reveals word by word with CSS keyframes, so it plays from the pre-rendered HTML.
- Sections reveal on scroll, project cards tilt on hover (mouse only), the project modal animates in and out,
  and the hero background has a light parallax.
- Animations only change `transform` and `opacity`. With reduced motion, movement is removed and only short fades remain.
- The project modal traps focus, closes on Escape or a backdrop click, and returns focus to the card that opened it.
- A skip link, visible focus outlines and semantic landmarks are included throughout.

## Deploy

### GitHub Pages (current setup)

The site deploys automatically to https://ravenity10.github.io/raven-cv/ from the
[Ravenity10/raven-cv](https://github.com/Ravenity10/raven-cv) repository.

- `.github/workflows/deploy.yml` builds and publishes on every push to `main`. It can also be run by hand
  from the repository's **Actions** tab.
- The workflow sets `VITE_BASE` (the `/raven-cv/` sub-path) and `VITE_SITE_URL` from the Pages settings,
  so nothing needs editing in the code. Asset paths use `import.meta.env.BASE_URL`.
- One-time setup: in the repository, go to **Settings > Pages** and set **Source** to **GitHub Actions**.
- A custom domain can be added in **Settings > Pages**. The workflow picks up the new base path automatically.

To preview the Pages build locally (in Git Bash, `MSYS_NO_PATHCONV=1` stops the path being rewritten):

```bash
MSYS_NO_PATHCONV=1 VITE_BASE=/raven-cv/ npm run build
```

### Other static hosts

The build output in `dist/` is a static site.

1. Set your domain in `.env` so the Open Graph tags use absolute URLs (social networks require this):

   ```
   VITE_SITE_URL=https://your-domain.com
   ```

2. Run `npm run build`.
3. Upload `dist/`, or connect the repository to a static host:
   - **Netlify / Cloudflare Pages / Vercel:** build command `npm run build`, output directory `dist`.
   - **Shared hosting or cPanel/Plesk:** upload the contents of `dist/` to the web root (`httpdocs` or `public_html`).
   - **Any host serving from a sub-path:** build with `VITE_BASE=/sub-path/`.
4. Optional: long cache headers for `/assets/*` (file names are content-hashed) and a short cache for `index.html`.

The screenshot script is not part of the build. Run it locally and commit `public/screens/` and `src/data/screens.json`.
